Java - Exceptions

In Java, an exception is an event that disrupts the normal flow of the program's instructions. It is an object which is thrown at runtime when an abnormal situation arises, such as accessing a null object, dividing by zero, or trying to open a file that doesn't exist.

Why Use Exceptions?

  • To handle runtime errors gracefully without crashing the program.
  • To separate error handling code from regular logic.
  • To provide meaningful messages when an error occurs.

Common Exception Types

  • ArithmeticException – division by zero
  • NullPointerException – accessing members on a null object
  • ArrayIndexOutOfBoundsException – accessing invalid array index
  • NumberFormatException – parsing invalid strings to numbers
  • FileNotFoundException – file not found on disk

Exception Hierarchy

All exception classes are subclasses of the Throwable class. The main subclasses are:

  • Error – serious issues like memory overflow (not meant to be caught)
  • Exception – problems that can be caught and handled

Syntax: try-catch block

try {
  // risky code
} catch (ExceptionType name) {
  // handling code
}

Example 1: Handling Division by Zero

int a = 10;
int b = 0;
try {
  int result = a / b;
} catch (ArithmeticException e) {
  System.out.println("Cannot divide by zero!");
}
Output:
Cannot divide by zero!

Multiple Catch Blocks

try {
  String str = null;
  System.out.println(str.length());
} catch (NullPointerException e) {
  System.out.println("Null pointer error!");
} catch (Exception e) {
  System.out.println("General exception caught.");
}

Finally Block

The finally block always executes after try and catch, even if an exception is not thrown.

try {
  int[] arr = new int[3];
  arr[5] = 10;
} catch (ArrayIndexOutOfBoundsException e) {
  System.out.println("Array index error.");
} finally {
  System.out.println("This block always runs.");
}
Output:
Array index error.
This block always runs.

Throwing Exceptions Manually

throw new IllegalArgumentException("Invalid input");

Throws Keyword

Used in method declaration to specify that a method might throw an exception.

public void readFile(String filename) throws IOException {
  // file reading logic
}

Creating Custom Exceptions

class MyException extends Exception {
  public MyException(String message) {
    super(message);
  }
}

Usage:

if (age < 0) {
  throw new MyException("Age cannot be negative");
}

Best Practices

  • Always catch the most specific exceptions first.
  • Never suppress exceptions silently (e.g., empty catch blocks).
  • Use custom exceptions for meaningful domain-specific error handling.
  • Log exceptions when needed, especially on the server side.
  • Don’t overuse checked exceptions—use them only when recovery is possible.

Conclusion

Java’s exception handling mechanism is powerful and allows developers to build robust applications that can detect, handle, and recover from runtime errors. Proper use of try-catch-finally and custom exceptions can significantly improve application reliability and maintainability.
