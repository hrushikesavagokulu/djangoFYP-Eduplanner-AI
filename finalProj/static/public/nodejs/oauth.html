OAuth Comprehensive Guide

OAuth Overview

OAuth is an open standard for access delegation commonly used to grant websites or applications limited access to user information on another service without exposing user credentials.

It allows users to authorize third-party applications to access their resources hosted on a service provider without sharing their password.

Key Components:

  • Resource Owner: The user who owns the data.
  • Client: The app requesting access.
  • Authorization Server: Issues access tokens after authentication.
  • Resource Server: Hosts the protected user data.

OAuth Flows

OAuth defines several authorization flows to accommodate different client types and use cases:

  • Authorization Code Flow:

    This is the most common and secure flow used by web and mobile apps.

    // Step 1: Redirect user to authorization server
GET /authorize?response_type=code&client_id=CLIENT_ID&redirect_uri=REDIRECT_URI&scope=read

// Step 2: After user login & consent, get authorization code in callback
GET /callback?code=AUTHORIZATION_CODE

// Step 3: Exchange code for access token (server-side)
POST /token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code&code=AUTHORIZATION_CODE&redirect_uri=REDIRECT_URI&client_id=CLIENT_ID&client_secret=CLIENT_SECRET
  • Implicit Flow:

    This flow was designed for single-page apps (SPAs), but is now discouraged due to security risks.

    // Step 1: Redirect user to authorization server requesting token directly
GET /authorize?response_type=token&client_id=CLIENT_ID&redirect_uri=REDIRECT_URI&scope=read

// Step 2: Access token is returned in URL fragment (#access_token=TOKEN)
  • Client Credentials Flow:

    Used for server-to-server communication, where no user is involved.

    // Request token using client credentials
POST /token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&client_id=CLIENT_ID&client_secret=CLIENT_SECRET
  • Resource Owner Password Credentials Flow:

    Exchanges user credentials directly for access tokens; recommended only for trusted clients.

    // Exchange username and password for token
POST /token
Content-Type: application/x-www-form-urlencoded

grant_type=password&username=USER&password=PASS&client_id=CLIENT_ID&client_secret=CLIENT_SECRET

OAuth Authorization Server

The Authorization Server is responsible for authenticating users, handling consent, and issuing access tokens and refresh tokens.

It must validate client credentials, user authentication, and scopes requested by the client app.

Typical endpoints:

  • /authorize - Handles user authorization and consent.
  • /token - Issues access and refresh tokens.
  • /revoke - Revokes tokens.

Example Express route for /authorize:

app.get('/authorize', (req, res) => {
  const { response_type, client_id, redirect_uri, scope, state } = req.query;
  // Authenticate user, ask for consent, then redirect with authorization code
  // ...
  res.redirect(`${redirect_uri}?code=AUTH_CODE&state=${state}`);
});

OAuth Access Tokens

Access tokens represent authorization granted to the client by the user and are sent with requests to access protected resources.

They can be:

  • Opaque tokens: Random strings with no meaning to clients.
  • JWTs (JSON Web Tokens): Self-contained tokens with claims encoded.

Tokens usually expire after a short duration for security reasons. Refresh tokens are long-lived and used to obtain new access tokens.

Example: Using access token to access protected API

GET /api/userinfo
Authorization: Bearer ACCESS_TOKEN

Using OAuth in Express.js

In Express.js, popular libraries like passport-oauth2 simplify OAuth integration.

Example with Passport OAuth2:

const passport = require('passport');
const OAuth2Strategy = require('passport-oauth2').Strategy;

passport.use(new OAuth2Strategy({
    authorizationURL: 'https://provider.com/oauth2/authorize',
    tokenURL: 'https://provider.com/oauth2/token',
    clientID: 'CLIENT_ID',
    clientSecret: 'CLIENT_SECRET',
    callbackURL: 'http://localhost:3000/auth/callback'
  },
  function(accessToken, refreshToken, profile, cb) {
    // Save or update user info here
    User.findOrCreate({ oauthId: profile.id }, function (err, user) {
      return cb(err, user);
    });
  }
));

app.get('/auth/provider', passport.authenticate('oauth2'));

app.get('/auth/callback',
  passport.authenticate('oauth2', { failureRedirect: '/login' }),
  (req, res) => {
    res.redirect('/');
  });

This setup handles the redirect, callback, token exchange, and user session management.
