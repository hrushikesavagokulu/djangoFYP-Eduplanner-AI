Mongoose Validation Guide

Introduction to Mongoose Validation

Mongoose validation is a powerful feature that ensures data integrity by enforcing rules on schema fields before saving documents to MongoDB.

Validation rules can be built-in or custom, synchronous or asynchronous, allowing flexible control over data.

Basic Schema Validation

Use built-in validators like required, min, max, maxlength, and enum to enforce simple rules.

const userSchema = new mongoose.Schema({
  name: { type: String, required: true },
  age: { type: Number, min: 0, max: 120 },
  email: { type: String, required: true, unique: true }
});

Here, name and email are required, age must be between 0 and 120, and email is unique.

Built-in Validators

Mongoose includes several built-in validators you can use on schema fields:

  • required — Ensures the field exists.
  • min, max — For numeric limits.
  • enum — Restricts values to a predefined set.
  • match — Validates strings against regex patterns.
  • maxlength, minlength — String length constraints.

Example:

const productSchema = new mongoose.Schema({
  category: { type: String, enum: ['Electronics', 'Books', 'Clothing'], required: true },
  price: { type: Number, min: 0, required: true },
  sku: { type: String, match: /^[A-Z0-9]{8}$/ }
});

Custom Validators

Define your own validation logic using a function. Return true for valid values or false for invalid.

const userSchema = new mongoose.Schema({
  password: {
    type: String,
    validate: {
      validator: function(value) {
        return value && value.length >= 6;
      },
      message: 'Password must be at least 6 characters long'
    }
  }
});

The message is shown when validation fails.

Async Validation

Sometimes validation requires asynchronous operations, like checking database uniqueness.

const userSchema = new mongoose.Schema({
  email: {
    type: String,
    validate: {
      validator: async function(value) {
        const existingUser = await User.findOne({ email: value });
        return !existingUser;
      },
      message: 'Email already exists'
    }
  }
});

This example checks if an email is unique before saving.

Validation Hooks (Middleware)

Use Mongoose middleware to run code before or after validation.

userSchema.pre('validate', function(next) {
  if (this.password && this.password.length < 6) {
    this.invalidate('password', 'Password too short');
  }
  next();
});

This runs custom validation logic before saving the document.

Handling Validation Errors

Mongoose throws a ValidationError when validation fails. You can catch it and process detailed errors.

user.save()
  .then(() => console.log('User saved!'))
  .catch(err => {
    if (err.name === 'ValidationError') {
      for (let field in err.errors) {
        console.error(err.errors[field].message);
      }
    }
  });

You can then send these messages to clients or logs.

Additional Validation Options

  • unique: Creates a unique index at the MongoDB level (note: not a validator but prevents duplicates at DB).
  • default: Provides a default value if none is given.
  • validate: You can pass an array of validators for multiple checks.
const postSchema = new mongoose.Schema({
  title: { type: String, required: true },
  tags: {
    type: [String],
    validate: [
      {
        validator: function(v) { return v.length > 0; },
        message: 'At least one tag required'
      },
      {
        validator: function(v) { return v.every(tag => tag.length >= 2); },
        message: 'Tags must be at least 2 characters'
      }
    ]
  }
});
