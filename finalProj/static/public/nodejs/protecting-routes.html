Protecting Routes in Express.js

Protecting routes is a crucial aspect of building secure web applications. It involves restricting access to certain parts of your application to authenticated and authorized users only.

Why Protect Routes?

  • To prevent unauthorized users from accessing sensitive data.
  • To enforce user permissions and roles effectively.
  • To secure critical actions such as modifying or deleting resources.

Common Methods for Protecting Routes

  1. Authentication Middleware: Checks if a user is logged in.
  2. Authorization Middleware: Ensures the user has permission to perform actions.
  3. Session or Token Validation: Uses sessions or JWT tokens to validate user identity.

Example: Authentication Middleware


function isAuthenticated(req, res, next) {
  if (req.isAuthenticated && req.isAuthenticated()) {
    return next();
  }
  res.status(401).send('Unauthorized');
}

Example: Authorization Middleware


function authorizeRoles(...roles) {
  return (req, res, next) => {
    if (!roles.includes(req.user.role)) {
      return res.status(403).send('Forbidden');
    }
    next();
  };
}

Using Middleware to Protect a Route


app.get('/admin', isAuthenticated, authorizeRoles('admin'), (req, res) => {
  res.send('Welcome to the admin dashboard');
});

Protecting Routes with JSON Web Tokens (JWT)

JWT is widely used for stateless authentication in APIs and SPAs.


const jwt = require('jsonwebtoken');

function verifyToken(req, res, next) {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).send('No token provided');

  jwt.verify(token, process.env.JWT_SECRET, (err, decoded) => {
    if (err) return res.status(401).send('Invalid token');
    req.user = decoded;
    next();
  });
}

Best Practices

  • Always validate tokens or sessions on every protected request.
  • Use HTTPS to encrypt token or session data during transit.
  • Implement role-based access control (RBAC) where necessary.
  • Handle errors gracefully and avoid leaking sensitive info.
