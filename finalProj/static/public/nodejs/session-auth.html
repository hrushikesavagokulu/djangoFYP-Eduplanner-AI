Session-Based Authentication in Express.js

Session-based authentication is a common method of maintaining user state and identity across multiple requests in web applications. It allows servers to keep users logged in using server-side sessions and client-side cookies.

1. Install Required Packages

To implement session-based authentication, install the following packages:

npm install express express-session body-parser

2. Basic Express Setup with Sessions

Here’s how to set up session-based authentication in your Express application:


// app.js
const express = require('express');
const session = require('express-session');
const bodyParser = require('body-parser');

const app = express();
const PORT = 3000;

app.use(bodyParser.urlencoded({ extended: true }));

// Setup session middleware
app.use(session({
  secret: 'my-secret-key',
  resave: false,
  saveUninitialized: true,
  cookie: { secure: false } // Set true in production with HTTPS
}));

// Simple login simulation
const USER = { username: 'admin', password: '1234' };

// Render login form
app.get('/login', (req, res) => {
  res.send(`
    <form method="POST" action="/login">
      <input name="username" placeholder="Username" required />
      <input name="password" type="password" placeholder="Password" required />
      <button type="submit">Login</button>
    </form>
  `);
});

// Handle login
app.post('/login', (req, res) => {
  const { username, password } = req.body;
  if (username === USER.username && password === USER.password) {
    req.session.user = username;
    res.redirect('/dashboard');
  } else {
    res.send('Invalid credentials');
  }
});

// Protected route
app.get('/dashboard', (req, res) => {
  if (req.session.user) {
    res.send(`Welcome ${req.session.user}, you are logged in! <a href="/logout">Logout</a>`);
  } else {
    res.redirect('/login');
  }
});

// Logout
app.get('/logout', (req, res) => {
  req.session.destroy(() => {
    res.redirect('/login');
  });
});

app.listen(PORT, () => {
  console.log(\`Server running on http://localhost:\${PORT}\`);
});

3. How It Works

  • User submits login form with valid credentials.
  • Server creates a session and stores user data.
  • Session ID is sent to the client via a cookie.
  • On future requests, the session ID is verified and the user is authenticated.

4. Important Notes

  • Always store sessions securely (use `secure: true` and HTTPS in production).
  • Use session store (e.g., Redis or MongoDB) for scalability in production apps.
  • Rotate session secrets periodically and handle session expiration properly.

5. Alternatives

For APIs and modern SPAs, consider using JWTs (JSON Web Tokens) instead of sessions.
