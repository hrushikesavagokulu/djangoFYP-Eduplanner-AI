Protecting Routes in Express.js

Protecting routes in an Express.js application means restricting access to certain endpoints based on authentication and authorization rules. This ensures that only authorized users can access sensitive resources or perform specific actions.

Why Protect Routes?

  • Prevent unauthorized access to private data.
  • Enforce permissions and user roles.
  • Secure sensitive operations like editing or deleting data.

Common Techniques to Protect Routes

1. Authentication Middleware

Verify that the user is logged in before allowing access to protected routes.


function isAuthenticated(req, res, next) {
  if (req.isAuthenticated && req.isAuthenticated()) {
    return next();
  }
  res.status(401).json({ message: 'Unauthorized: Please log in' });
}

2. Authorization Middleware

Check if the authenticated user has permission to access a resource.


function authorizeRoles(...allowedRoles) {
  return (req, res, next) => {
    const userRole = req.user.role;
    if (!allowedRoles.includes(userRole)) {
      return res.status(403).json({ message: 'Forbidden: Insufficient permissions' });
    }
    next();
  };
}

Using Middleware to Protect Routes

Combine authentication and authorization middleware to protect routes:


app.get('/dashboard', isAuthenticated, (req, res) => {
  res.send('Welcome to your dashboard');
});

app.post('/admin/settings', isAuthenticated, authorizeRoles('admin'), (req, res) => {
  res.send('Admin settings updated');
});

Protecting Routes with JWT (JSON Web Tokens)

JWT is commonly used for stateless authentication in APIs.


const jwt = require('jsonwebtoken');

function verifyToken(req, res, next) {
  const token = req.headers['authorization'];
  if (!token) return res.status(401).json({ message: 'No token provided' });

  jwt.verify(token, process.env.JWT_SECRET, (err, decoded) => {
    if (err) return res.status(401).json({ message: 'Invalid token' });
    req.user = decoded;
    next();
  });
}

Protecting Routes with Sessions

Express-session allows you to protect routes by checking if a session exists.


app.use(session({ secret: 'your-secret', resave: false, saveUninitialized: false }));

function checkSession(req, res, next) {
  if (req.session && req.session.userId) {
    return next();
  }
  res.redirect('/login');
}

Best Practices for Route Protection

  • Always authenticate before authorizing.
  • Use HTTPS to protect tokens and session cookies.
  • Keep secret keys and tokens secure and out of source code.
  • Implement proper error handling to avoid leaking sensitive info.
  • Use rate limiting and other security middlewares to protect endpoints.

Summary

Protecting routes is essential to building secure Express.js applications. By combining authentication and authorization middleware, you can control who accesses your application’s features and data, providing a safer experience for your users.
