Error Handling in Express.js

Why is Error Handling Important?

Error handling ensures that your Express.js application can gracefully respond to unexpected issues, providing meaningful feedback to users and preventing the server from crashing.

Basic Error Handling with Middleware

Express provides a special error-handling middleware that takes four arguments: (err, req, res, next). This middleware catches errors from synchronous or asynchronous code. 

app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(500).send('Something went wrong!');
});

Throwing Errors in Routes

You can throw errors in your routes to be caught by the error handler:

app.get('/error', (req, res, next) => {
  const err = new Error('This is a forced error');
  err.status = 400;
  next(err);
});

Handling Errors in Asynchronous Code

Errors in asynchronous functions should be passed to next() for proper handling:

app.get('/async-error', async (req, res, next) => {
  try {
    await someAsyncFunction();
    res.send('Success!');
  } catch (err) {
    next(err);
  }
});

Custom Error Handling Middleware

You can create custom middleware to handle specific error types:

function notFoundHandler(req, res, next) {
  res.status(404).send('Page Not Found');
}

function generalErrorHandler(err, req, res, next) {
  res.status(err.status || 500);
  res.json({
    message: err.message,
    error: process.env.NODE_ENV === 'production' ? {} : err.stack
  });
}

app.use(notFoundHandler);
app.use(generalErrorHandler);

Best Practices for Error Handling

  • Always call next(err) in asynchronous code to forward errors.
  • Use proper HTTP status codes to reflect error types.
  • Log errors for debugging but avoid exposing sensitive info to clients.
  • Handle 404 errors with a dedicated middleware.
  • Consider using third-party libraries like http-errors for easier error management.

Useful Packages for Error Handling

  • http-errors – Create HTTP errors with ease.
  • express-async-errors – Simplify async error handling.
  • winston or morgan – For logging errors and requests.
