Bit Fields

In C, a bit field allows the allocation of a specific number of bits to a variable inside a struct. This is useful when memory is a constraint or when you need fine-grained control over hardware-specific values.

Why Use Bit Fields?

  • Efficient use of memory.
  • To model data closely related to hardware registers or binary protocols.
  • To store boolean flags compactly.

Syntax

struct {
  unsigned int flag1 : 1;
  unsigned int flag2 : 1;
  unsigned int counter : 4;
} status;

In this example, flag1 and flag2 each use 1 bit, and counter uses 4 bits. The total storage is less than a full byte compared to storing them as separate integers.

Example

#include <stdio.h>

struct status_flags {
  unsigned int carry : 1;
  unsigned int zero : 1;
  unsigned int sign : 1;
  unsigned int overflow : 1;
};

int main() {
  struct status_flags flags = {1, 0, 1, 0};
  
  printf("Carry: %d\\n", flags.carry);
  printf("Zero: %d\\n", flags.zero);
  printf("Sign: %d\\n", flags.sign);
  printf("Overflow: %d\\n", flags.overflow);

  return 0;
}

Important Notes

Bit fields must be used with care as their layout in memory can be implementation-specific (e.g., order of allocation and padding).
Bit fields cannot be taken by reference (e.g., &status.flag1 is invalid) and may not be portable between different compilers or platforms.

Unnamed Bit Fields

Unnamed fields can be used to introduce padding: 

struct {
  unsigned int a : 3;
  unsigned int   : 2; // unnamed 2-bit padding
  unsigned int b : 3;
} padded;

Bit Fields vs Bitwise Operators

Bit fields simplify structure but are not a replacement for &, |, ^, etc., when doing bit manipulation across variables or outside structs.
