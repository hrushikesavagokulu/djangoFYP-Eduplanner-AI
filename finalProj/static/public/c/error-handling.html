Error Handling

Error Handling in C

In C programming, handling errors properly is important to write robust programs that can gracefully deal with unexpected situations like failed file operations, invalid inputs, or memory allocation errors.

Common Error Handling Techniques

  • Return codes: Many functions return special values (e.g., -1, NULL) to indicate failure.
  • errno and perror: The global variable errno stores error codes set by system calls and library functions. perror() prints a descriptive error message.
  • Assertions: Use assert() during development to catch programming errors.

Using Return Codes

Check the return value of functions and handle errors explicitly:

#include <stdio.h>

int main() {
    FILE *fp = fopen("data.txt", "r");
    if (fp == NULL) {
        printf("Failed to open file.\n");
        return 1; // Exit or handle error
    }
    // Proceed if file opened successfully
    fclose(fp);
    return 0;
}

Using errno and perror

errno is a global variable set by system/library functions on failure. You can include <errno.h> and <string.h> to inspect it. perror() prints a descriptive error message to stderr based on the current errno.

#include <stdio.h>
#include <errno.h>
#include <string.h>

int main() {
    FILE *fp = fopen("nonexistent.txt", "r");
    if (fp == NULL) {
        perror("Error opening file");
        printf("errno value: %d\n", errno);
        printf("Error description: %s\n", strerror(errno));
        return 1;
    }
    fclose(fp);
    return 0;
}

Using assert()

assert() from <assert.h> tests assumptions and aborts the program if an expression is false (useful for debugging):

#include <assert.h>

int main() {
    int x = 5;
    assert(x == 5); // Passes silently
    assert(x != 5); // Fails and aborts program
    return 0;
}
Note: Assertions should not be used for runtime error handling in production; they are mostly for debugging.

Best Practices for Error Handling

  • Always check function return values, especially for I/O, memory allocation, and system calls.
  • Use perror() or strerror() to provide informative error messages.
  • Clean up resources (close files, free memory) before exiting on error.
  • Document possible errors your functions might return.
